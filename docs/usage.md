# Research-Agent の画面の使い方

調べたいことを文で頼むと、エージェントが公開の Web とデータベースを調べ、出典付きの報告を書きます。この画面では、依頼を送り、調べている様子を見て、報告と過去の調査を読みます。

起動と初期設定は [setup.md](setup.md) を見てください。この説明書は、起動した後の使い方です。

## 1. 開き方

| 開き方 | 住所・操作 | 向いている使い方 |
|---|---|---|
| ブラウザ | http://localhost:8100/ui/ | いちばん手軽 |
| アプリ（PWA） | ブラウザで開き、メニューの「アプリをインストール」 | 単独の窓で使う。調査の知らせを受ける |
| デスクトップアプリ | `Research-Agent_<版>_x64_ja-JP.msi` を入れ、スタートメニューから | 窓を閉じてもトレイに残り、知らせを続ける |

どれも同じ画面で、同じ調査の履歴を見ます。

### 初めて開いたとき

- **ブラウザ・アプリ**: 「ゲートウェイの鍵」の欄が出たら、`.env` の `AGENT_API_KEY` の文字列を入れて「保存して開き直す」。ブラウザが覚えるので、次からは出ません
- **デスクトップアプリ**: 「つなぐ先」が出ます。住所に `http://localhost:8100`、鍵に `AGENT_API_KEY` を入れて「確かめてつなぐ」。鍵は Windows の資格情報マネージャーに入ります

## 2. 画面の見方

画面は左・中・右の 3 列です。

- **左: 履歴** … これまでの調査。上の「＋ 新しい調査」で、何も開いていない状態に戻る。下の「設定」で設定のパネルを開く
- **中: チャット** … 依頼と報告。上の 1 行は、次に送る依頼に効く設定（エージェント・プリセット・モデル）。押すと設定が開く
- **右: 作業記録** … エージェントが何をしているか。流れの図（Flow）と木（Tree）を切り替えられる
- 境界をドラッグすると、各列の幅を変えられる（矢印キーでも。設定 › 表示 で既定に戻す）

チャットの上の 1 行の下に、左に線の付いた注意が出ることがあります。送る前に読んでください（[8 章](#8-困ったとき)）。

## 3. 調べる

1. 下の欄に依頼を書き、**Enter** で送る（改行は Shift + Enter。日本語の変換を確定する Enter では送らない）
   - 例: 「東京タワーの高さ」「はやぶさについて調べて」「青学の伊藤先生について」
   - **論文**: 「論文」「研究」「文献」などを入れると、論文のデータベース（Crossref・arXiv・J-STAGE。登録すれば OpenAlex）も引く。例: 「CRISPR の主な論文」「深層学習の先行研究」
   - **商品の価格**: 「価格」「値段」「最安」「在庫」などを入れると、Yahoo!ショッピング・楽天市場の商品検索も引く（登録したとき。[setup.md](setup.md)「論文と商品の価格」）。価格は取得日時付きで、変わることがある。例: 「iPhone 16 の価格」
   - 欄の上の「最近の依頼」を押すと、その文が欄に入る（送るのは自分）
2. チャットに「調べています」の吹き出しが出て、右の作業記録が伸びていく。1 件に数分かかる（研究室の LLM の速さによる）
3. 終わると、報告が吹き出しに出る

### 調べている間にできること

- **一時停止・再開**: 作業記録の上のボタン。一時停止は、作業の区切りで止まる（すぐではない。止まると「作業の区切りで止まった」と出る）
- 調べている間は、新しい依頼は送れない（送るボタンが「調査中」になる）。別の履歴を開いて読むことはできる

### 聞き返されたとき

対象がはっきりしない依頼（同じ名前の人・物が複数あるなど）では、エージェントが聞き返します。

- 候補に番号が付いていれば、番号のボタンを押すか、欄に番号を書いて送る
- 候補にないときは、欄に具体的な内容を書いて送る（例: 「小惑星探査機のはやぶさ」）
- 答えを待っている間、欄の文字が「答えを入力（番号でも可）」に変わる

### 報告の読み方

- 見出しごとに、確かめた事実が並ぶ。文の後の **小さな番号**（出典番号）を押すと、その出典のページを作業記録の中で示し、そのページで確かめた記述と引用を出す
- 最後の「出典」に、番号ごとのページの題と URL
- 「確かめきれなかったこと」「同じ名前の人の資料（本人のものか確かめていない）」の節は、報告の本文に使わなかったものと、その理由
- 報告の下の「報告をコピー」で、Markdown の文のまま写せる
- 「報告と成果物を保存した」と出たら、保存まで終わっている

## 4. 作業記録（右）

| 表示 | 見えるもの |
|---|---|
| **Flow**（流れの図） | 工程（判定・判断・検索・ページを読む・画像・食い違い・報告）を箱で並べ、判断と各工程の行き来を線で示す。線の「×3」は通った回数。点線と「LLM の選択 ✕」は、モデルが選んだがプログラムが変えた行き先 |
| **Tree**（木） | 判断ごとに枝が伸びる。検索の結果、読んだページ、データベースの記録、画像、網羅表（観点ごとに出典条件を満たしたか）まで細かく見える |

- 箱を押すと、右に詳細（そのときの記述・理由・時間など）が出る。✕ で閉じる
- 拡大・縮小はホイール（スマホは 2 本指）、移動はドラッグ。右下の「全体」で全体に合わせ直す
- 上の表示は「ライブ」（動いている調査）か「履歴を 8 倍で再生」（終わった調査）
- 状態の言葉: 「処理中」「モデルに依頼中」「原文に引用が見つかった記述」「出典条件を満たした観点」など。数字は、エージェントが記録したものをそのまま数えている

## 5. 履歴

- 行を押すと、その調査を開く。終わった調査は、記録を 8 倍の速さで再生する（再生中は作業記録の上のボタンで止められる）
- 行の右の「…」から
  - **詳細を見る**: 始めたときの設定・使ったモデル・応答したモデルと費用・LLM とのやり取りの全文（「テキストで開く」「保存」）
  - **削除**: 確かめてから、その調査の履歴・報告・作業記録を消す（元に戻せない。Open WebUI の会話は残る）。動いている調査は、終わってから消せる
- チャットの上の小さな行（「応答したモデル: …」「設定: …」）を押しても、開いている調査の詳細が出る

## 6. 設定（左下の「設定」）

### 調査

- **プリセット**: 標準（時間の上限 900 秒・ページ 12）、すばやく（420 秒・6）、くわしく（1800 秒・24）
- **欄**: 時間の上限（秒。答えを待つ時間は含まず、報告を書く 5 分を含む）、読むページの数、画像も探す
- 既定から変えた欄には印が付く。プリセットと違う組み合わせは「カスタム」
- 対象エージェント（調査エージェント・チャット）を選べる。チャットは作業記録を持たないので、画面はチャットだけになる

下のボタンの違い:

| ボタン | 効き方 |
|---|---|
| この依頼に適用 | 次に送る **1 件だけ**。チャットの上の行に「この依頼だけ」と出る。送ったら元に戻る |
| このブラウザの既定値に保存 | 次の依頼から **毎回**（このブラウザ・アプリだけ） |
| 標準に戻す | 編集中の値を、エージェントの既定に戻す（適用か保存を押すまで効かない） |

### モデル

- **全役割共通**: 判断・ページの読み取り・画像の確認・報告をすべて同じモデルにする。「既定」は窓口の設定どおり
- **役割ごとの上書き**: 役割ごとに選ぶ。役割に要る能力（JSON スキーマ・画像）がないモデルは選べない
- **最終的な割り当て**: 実際に使うモデル。外部のモデル（Claude など）を使うときは、依頼文と読んだページを外部に送ること、料金が出る

### API キー

外部の Web API（Anthropic・OpenAI・Google Gemini・OpenRouter）の鍵を入れて、モデルを足します。

1. 鍵を入れて「判別して確かめる」（鍵の形から提供元を判別し、モデル一覧で確かめる）
2. 足すモデルにチェック。能力と値段（100 万トークンあたりの USD。無料なら 0）を確かめる
3. 「選んだ N 件を足す」

鍵はモデルの窓口だけが持ち、画面には末尾 4 文字だけが出ます。外すときは一覧の「外す」。

### 接続と使用量

- エージェント・研究室の LLM・検索（SearXNG）・モデルの窓口に、つながっているか
- モデルごとの呼び出し回数・トークン・費用、今日の推計費用、費用の上限（既定: 1 日 $5・1 調査 $1。上限に達すると有料のモデルを呼ばない）
- デスクトップアプリでは、ここで「つなぐ先を変える」

### 表示

- ペインの幅を既定に戻す
- **調査の知らせ**: 入れると、画面が後ろにあるときに、開いている調査が「答えを待っています」「報告ができました」「エラーで止まりました」と OS の通知で知らせる（初めて入れるとき、許可を聞かれる）

### 履歴の詳細の「この設定を使う」

過去の調査を始めたときの設定とモデルを、次の 1 件に読み込みます（「過去の設定」と出る）。今は使えないモデルがあれば、理由と代わりのモデルがチャットの上に出ます。

## 7. 狭い画面・スマホ

- 幅が狭いと、履歴は左上の ☰ で出し入れする
- さらに狭いと、上の「チャット」「作業記録」で切り替える（切り替えても、入力中の文と調査の受信は続く）

## 8. 困ったとき

| 出ること | 意味と直し方 |
|---|---|
| チャットの上に「VPN を確認」 | 研究室の LLM につながらない。Cisco Secure Client で VPN（agvpn.aoyama.ac.jp/ac-access）につなぐ |
| 「検索につながらない」 | SearXNG が止まっている。`docker compose -p research-agent up -d searxng` |
| 「エージェントにつながらない」 | 調査エージェントが止まっている・起動中。少し待つか、[setup.md](setup.md) の「うまくいかないとき」 |
| 「一覧を読めません」 | ゲートウェイにつながらない（Docker Desktop が止まっている、など）。画面は開くが、履歴と調査は出ない |
| 鍵の欄が出る | 鍵が違う・まだ入れていない。`.env` の `AGENT_API_KEY` を入れる |
| 「◯◯ は使えない（…）→ △△ を使う」 | 選んだモデルが一覧から消えた・役割に要る能力がない。代わりのモデルで送られる。設定 › モデル で選び直せる |
| 「外部のモデルに依頼文と読んだページを送ります」 | 外部の Web API のモデルを選んでいる。送ってよいか確かめる |
| 右下に「画面の新しい版があります」 | 画面が更新された。「再読み込み」で新しい版になる（調査の途中なら「あとで」でよい） |
| 「接続が切れた（最後に受け取った …）」 | 調査の受信が切れた。自動でつなぎ直す。続くなら画面を開き直す（調査自体は続いている） |
| 報告が「確認できた事実がありません」 | 時間の上限で十分に読めなかった、または対象が見つからなかった。「確かめきれなかったこと」の理由を見て、プリセットを「くわしく」にするか、依頼を具体的にする |

- 調べ方の中身（何を送り、何が返ったか）を確かめたいときは、履歴の「…」→「詳細を見る」→「LLM とのやり取り」
- 終わった調査を、再生せずにすぐ全部出したいときは、住所の後に `?run=<調査の ID>&speed=0` を付けて開く
