## 2. 今回追加したものの中身

### フェーズ 3

| 項目 | 実装 | 設計書 |
|---|---|---|
| 転載の見分け | 読んだページの本文から署名（文字 8-gram の MinHash、64 個）を作り、先に読んだページと見積もりの類似度が 0.6 以上なら写しとして記録する。網羅表は写しを独立した出典として数えない。出典一覧に「[n] とほぼ同じ文章」と書く（`agent/reprints.py`） | 6.3 |
| ページ単位の Tier の調整 | 深掘りの LLM が「上げる / そのまま / 下げる」と理由を返す。プログラムが幅を確かめて入れる（1 段だけ。上げるのは Tier 3〜4、下げるのは Tier 1〜2。理由がなければ認めない）。網羅表・出典一覧・画像の判定（V-2）がこの Tier を使う（`tiers.page_tier`） | 6.3 |

### フェーズ 6

| 項目 | 実装 | 設計書 |
|---|---|---|
| L3 分野別データベース | 対象の種類に合うデータベースの公開 API を直接呼ぶ（`tools/databases.py`、`config/databases.toml`）。記録は API の値から作った文章として深掘りし、引用もその文章と照合する。画像があれば L3 の候補にする | 8.1, 6.6 |

## 4. 実際の環境での確認

`uv run scripts/check_env.py` で環境を確かめてから、CLI（`scripts/agent.py`）で実行した。

| 例 | 時間 | 結果 |
|---|---|---|
| 例 B（青山学院大学の情報テクノロジー学科のマーティン先生） | 357 秒 | L3 で ORCID の記録 1 件を先に読み、出典 [1]（Tier 2）になった。顔写真は大学のページから確認済み。出典は Tier 1〜2 の 4 件 |
| 例 C（オリンパス ペン EE-3、外観の写真付き） | 683 秒 | ジャパンサーチは兄弟機種（ペン S・ペン D）だけで、名前の照合で正しく除いた（0 件）。Commons の EE-3 の写真 2 枚が確認済みで、「画像で確かめた特徴: クロム仕上げとブラックレザー」が付いた。追跡用パラメータの違うページの重複はなくなった（前回は同じページが出典に 4 回） |

- 例 C の出典はすべて Tier 4（販売店・個人のサイト）で、「出典が限られること」に書かれた。EE-3 は Wikidata に項目がないため、公式サイト（P856）の Tier 1 扱いはこの例では働いていない
- 生物の例（ニホンカモシカ。L3 の iNaturalist・GBIF と L5 の周辺の画像の確認）は、まだ実際の環境で流していない
